# STAR Methods — 4.2 Build a pooled library

_Working document, 2026-11-23. Derived from `_data/protocols.yml`
(`workflows:`, id `4.2`) and from the citation audit in
`00-citation-audit.md`. Intended practice; the facility installs April 2027.

closes it has no route yet._

**Citation status: no single published source.** A composite of four
published components (Golden Gate, overhang-set fidelity, SPRI, SPRI ratio
size selection) over a pooled-library architecture that is standard in the

## Internal inconsistency found during this audit — resolved

The `inputs:` block specified **electrocompetent** cells while the
transformation step specified **the pulse as a plate move between the two
temperature-controlled deck nests, exactly as 4.14** — which is heat shock,
and heat shock does not work on electrocompetent cells.

**Resolved 2026-11-23 in favour of the step: the cells are chemically
competent.** The deciding evidence is that there is no electroporator
anywhere in the device set, so electrocompetent cells cannot be transformed
on this system at all; 4.14 names chemically competent cells for the same
pulse; and on-deck heat-shock transformation is a settled decision. The
`inputs:` line was corrected in `_data/protocols.yml` with the reasoning
recorded beside it.

## Resource availability

**Lead contact.** As 4.1.

**Materials availability.** The product is a library in liquid culture,
never plated for colonies. It is a pool, not a set of clones, and cannot be
redistributed as individual members.

**Data and code availability.** The sequencing read that says what is in the
pool is the protocol's real output and **has no route yet** — the repository
records the NGS path as undecided between an in-lab Nanopore and a campus
core. Until that is settled this protocol produces a library whose contents
are unknown.

## Experimental model and subject details

*E. coli*, competent, used as an amplification host for the pool and nothing
else. No colony is ever picked and no clone is isolated: transformation is
here only to amplify a library. For an arrayed build that skips cells
entirely, see 4.13.

## Method details

1. **Retrieve the subpool.** Pool PCR built acoustically at 384, one subpool
   per library; one of four cycler blocks runs it while the other three stay
   available.
2. **Size-select the product.** SPRI at 0.8× on the 96-channel head beside
   the deck magnet, ~32 min at 384. This is the only size selection the deck
   has.
3. **Assemble into the linearised backbone.** Type IIS digestion–ligation
   with BsaI-HFv2 and T4 ligase, delivered from the tube by a
   positive-displacement channel because glycerol-based enzyme mixes will
   not transfer acoustically. Cycled on an ATC block.
4. **Clean up and transform.** A second SPRI, then the pulse (see the
   inconsistency note above).
5. **Recover and outgrow as a pool.** Recovery medium bulk-dispensed
   immediately, then a shaking incubator position overnight. **The pool is
   the product**; plating it would pick a handful of members out of a
   library.
6. **Sequence the pool.** Off the deck either way — nothing on this system
   reads sequence.

## Quantification and statistical analysis

The quantity that matters is library representation, and it is measured by
the sequencing step that does not yet exist. Nothing earlier in the protocol
reports diversity: the 0.8× SPRI sets a lower size bound rather than a
composition, and the outgrowth is unsampled. Until the NGS path is decided,
this protocol has no quantification stage, and that is the honest statement
of its status rather than a gap in this document.
